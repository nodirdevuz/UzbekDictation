# Распознавание во время речи (потоковая транскрипция)

Дата: 02.08.2026. Статус: одобрено владельцем, реализуется.

## Задача

Ожидание после ⌘ линейно растёт с длиной диктовки. Замеры 02.08.2026 (лог приложения):

| Речь | После обрезки | Ожидание |
|---|---|---|
| 8,9 с | 7,8 с | 1,3 с |
| 37,3 с | 29,1 с | 4,0 с |
| 79,6 с | 59,9 с | 8,4 с |
| 88,0 с | 74,0 с | 14,3 с |

Скорость распознавания ~0,13× от длительности аудио — это потолок для i9-9880H на
CPU (Metal здесь в 24 раза медленнее, проверено; все параметры whisper уже выжаты:
greedy, потоки = физические ядра, адаптивный `audio_ctx`, обрезка тишины, сжатие пауз).

Причина ожидания не в скорости whisper, а в том, что он **простаивает всю диктовку**
и начинает работать только после остановки.

## Решение

Резать записанное на куски по паузам и распознавать их **во время записи**. После ⌘
остаётся дораспознать только хвост — последнюю фразу.

Ожидаемо: ожидание перестаёт зависеть от длины диктовки и определяется длиной
последней фразы. Для 88 с речи — 14,3 с → 1,5–3 с.

## Где резать

Только по паузам, **ровно посередине паузы** — так ни одно слово не разрывается.

- пауза = ≥ 0,6 с ниже порога громкости (тот же порог, что в `trimSilence`:
  `max(0.006, peak * 0.08)`);
- кусок не короче **6 с** — на коротких обрывках whisper теряет контекст и ошибается;
- кусок не длиннее **25 с** — если пауз нет, аварийный рез в точке минимальной
  энергии в окне 20–25 с;
- пауза должна быть **закрытой** (речь после неё возобновилась) — иначе режем по
  «горячему» краю, где человек ещё не договорил;
- к каждому куску применяется та же обработка, что сейчас ко всей записи:
  `trimSilence` → `compressPauses` → `padIfShort`.

Существенное обстоятельство: в `whisper_bridge.c` стоит `no_context = true` — текст
предыдущего сегмента и сейчас не идёт в подсказку следующему. Куски и так
распознаются независимо, поэтому нарезка не меняет модель работы декодера.

## Очередь и потоки

Один whisper-контекст на язык, все вызовы идут через существующую последовательную
очередь `rubai.whisper` — параллельные вызовы в один контекст недопустимы.
Порядок гарантирован самой очередью: результат хвоста приходит последним, значит
служит сигналом «всё готово».

- фоновые куски — **4 потока**, QoS `.utility` (владелец параллельно работает на
  этой же машине; полная загрузка 8 ядер во время речи мешала бы);
- хвост после ⌘ — **8 потоков**, QoS `.userInitiated`.

Отставание не накапливается: речь идёт в реальном времени, распознавание на
половине ядер — примерно в 5 раз быстрее реального времени.

## Поток данных

```
микрофон → Recorder.samples ─┬─ [таймер 0,4 с] cutPoint(хвост) → кусок → очередь → parts[i]
                             └─ ⌘ → stop() → хвост → очередь (8 потоков) → parts[last]
                                                                              ↓
                                          parts.joined(" ") → dropHallucination
                                                            → collapseRepeats → вставка
```

`Recorder` получает доступ к накопленному без остановки записи (`sampleCount`,
`slice(from:to:)`). Курсор «сколько уже отдано» живёт в `StreamTranscriber`.

## Краевые случаи

| Случай | Поведение |
|---|---|
| ⌘⌘⌘ — смена языка на лету | Счётчик поколения +1, курсор и накопленные куски сбрасываются, запись распознаётся заново с начала. Иначе часть текста осталась бы на другом языке. Результаты уже запущенных кусков отбрасываются по поколению |
| ⎋ отмена | Поколение +1, куски отброшены; запоздалый результат не может всплыть в следующей диктовке |
| Запись короче 6 с | Ни одного реза не произошло, работает ровно как сейчас — один проход |
| Тихий кусок (peak < 0,012) | В whisper не отправляется вовсе — иначе он выдумает «[музыка]» |
| Хвост короче 0,35 с или тихий | Не распознаётся; в очередь ставится барьер, чтобы дождаться уже запущенных кусков |
| Тишина за всю запись | Проверка `peakLevel` по всему материалу, как сейчас |
| Модель ещё грузится | Куски копятся в очереди и разбираются по мере готовности — потери нет |

## Откат

Пункт меню «Gapirganda tanish (tezroq)», по умолчанию включён, состояние в
UserDefaults. Выключён — работает прежний путь целиком, код старого пути не удаляется.
